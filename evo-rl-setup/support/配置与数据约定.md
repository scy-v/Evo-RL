# 配置与数据约定

## SFT 设置

核对基准是仓库 `docs/source/pi05.mdx` 的 SFT 示例；主 README 第 6 步是后续 ACP，不是初始普通 SFT。

核心设置与 SFT 示例及默认值一致：bfloat16、全参、编译开启、梯度检查点开启、冻结视觉关闭、仅训练 expert 关闭、PEFT 关闭、ACP/RA-BC/RTC 关闭；默认图像处理、tokenizer、QUANTILES 归一化、chunk=50、内部 state/action 上限 32、token 长度 200 均未改动。
优化器沿用默认 AdamW：lr=2.5e-5、betas=(0.9,0.95)、eps=1e-8、weight_decay=0.01、梯度裁剪=1.0；默认 warmup=1000、decay=30000、末端 lr=2.5e-6。总步数小于 30000 时仓库会自动缩放调度。

用户指定的适配：4 卡、每卡 batch 16（全局 64）、30000 步、每 5000 步保存、本机数据与输出地址。W&B 只上传日志：enable=true、disable_artifact=true；HF 模型上传关闭，模型仅在本地保存。

## 离线选维度

训练数据适配位于 DatasetConfig、datasets/factory.py、datasets/state_selection.py；PI05 模型、处理器、训练循环保持基线实现。

`OBS_INDICES` 为从 1 开始的索引，按参数顺序选列，支持重排；也可用零基 `dataset.state_indices`，显式配置优先。数据加载完成后通过一次 HF map 得到整张新表，替换训练使用的表；取样和采 batch 时不再筛选。状态名称、维度和对应统计同步选择，count、动作、图像和原始数据文件不改。该功能要求 streaming=false。

原始数据有 48 维 state，当前 PI05 使用第 1–19 维；200 个 episode、67740 帧、15 Hz、两路图像、7 维动作。原有末端增量动作语义不变，未增加额外 delta transform。
推理与在线调用由调用方提供已准备好的 19 维输入，不通过 OBS_INDICES 筛选。

## UR rollout 采集与数据格式

采集入口为 `lerobot.scripts.ur5e_rollout`，配置为 [rollout.yaml](../../examples/ur5e/rollout.yaml)。运行依赖并入当前 `evo-rl` 环境的 `ur5e` extra，不需要 RLinf/OpenPI 环境。`data` 软链接到 `/data/suchenyu/evo-rl/data`，新增数据不写进仓库磁盘目录。

模型层复用[原生 PI05 loader](../../src/lerobot/scripts/ur5e_inference/policy.py)，取原始 state 的第 1–19 维和两路原始 RGB。默认预测 50 步、执行前 10 步、15 Hz、去噪 10 步；保持同步推理和原 UR 控制，接管释放后继续当前 chunk 剩余动作，没有异步重规划或后台持续力控。动作和图像不再经过 RLinf/OpenPI transforms。

`model.conditioning=auto` 读取 checkpoint 的 `train_config.json`：SFT 使用原始任务文本，ACP 使用正优势条件；缺少训练配置时必须显式选 `sft` 或 `acp`。写入数据集的 task 文本不带优势条件，供后续重新打标签。

新数据和转换副本采用一致的最小训练 schema：原始 48 维 `observation.state`、7 维实际执行 `action`、两路视频和 LeRobot 标准索引；逐帧 `complementary_info.is_intervention` 为 float32，episode metadata 中 `episode_success` 为 `success` 或 `failure`。旧 rollout 的逐帧成功标签必须在每个 episode 内一致才能转换；原始 `intervene_flag` 转为接管字段。SFT 按已确认的全部成功假设补标签，纯人工示范的接管标记为 0。

转换器只生成新副本，保留原始观测、动作、视频及来源 sidecar；更新字段统计，不伪造无法恢复的 `policy_action`，也不复用旧的优势标签。来源与假设保存在 `meta/dataset_provenance.json`，合并池另保存 `meta/dataset_sources.json`；复用命令见[训练命令](../训练命令.md)。

续采需在 YAML 中同时设置 `record.task.resume=true` 和确切的 `record.storage.root`；`num_episodes` 是本次追加数量。键盘监听需要本地桌面/X 会话，`display=false` 仅关闭 Rerun，不提供纯 SSH 键盘控制。

数据目录采用 `data/lerobot/<repo_id>`，不增加机器人型号层。实验名作为独立目录：`data/lerobot/insert_black_rack_into_blue_slot/`，下设 `demonstrations`、`rollout_round_001`、`training_round_001`。本地 repo_id 使用 `<实验名>/<数据集名>`；训练池是前两者的派生数据，不是额外采集来源。合并前设置 `HF_LEROBOT_HOME` 为仓库的 `data/lerobot`，即可使用官方 `lerobot-edit-dataset --operation.type=merge`。

采集 YAML 的 `record.storage.root` 与 `record.repo_id` 保持同一布局，首轮示例使用 `rollout_round_001`。新建采集使用不存在的输出目录；分多次采集同一轮时使用相同 root 并显式开启 resume。策略权重由 YAML 指定。

## 后续循环约定

当前采集适配和旧数据转换已完成；真机采集及 value/ACP 训练尚未执行，验证范围见[测试进展](../测试进展.md#2026-11-13)。独立 SFT 评估入口的日志仍不是 LeRobot 训练数据，不能作为采集数据直接合并。

当前 value 和 ACP 的训练入口均调用 `datasets.factory.make_dataset()`；该函数的多数据集分支直接抛出 `NotImplementedError`，因此现有流程需将多份数据整理为单个训练池。合并使用官方 CLI，内部调用 `datasets.dataset_tools.merge_datasets()` 和 `aggregate_datasets()` 处理索引、任务、视频位置和统计。CLI 的 `--root` 是单个数据集目录，不会拼接输入 repo_id；使用多个数据集时不传该参数，通过 `HF_LEROBOT_HOME` 选择共同存储位置。若要直接指定多个独立数据集，需要另外实现并验证多数据集加载。

合并保留原始 48 维 state，不落盘选维。value 训练和推理保持相同输入；只在 PI05 SFT/ACP 命令前内联 `OBS_INDICES`，不要全局 export 给 value 阶段。含失败轨迹的当前池采用默认 `legacy` reward；只接受成功轨迹的 reward 模式不能直接用于该池。

本地已选定的跨轮方案：每轮重新建立 value，加载预训练骨干而不加载上一轮 value checkpoint；在累计数据上训练，再对整个累计池重新计算 value/advantage/indicator；ACP 每轮固定从 `checkpoints/pretrained/pi05_base` 初始化。该方案是本地采用的 RECAP 式流程，不代表源码强制要求。

用于 rollout 的 checkpoint 与 ACP 训练的 `policy.pretrained_path` 相互独立。下一轮在 YAML 中指定新 ACP 权重和新的采集输出目录，合并上一轮累计池与新 rollout；训练时更新轮次、合并池、字段 tag 和输出目录，固定基座不变。框架不会自动切换阶段或查找历史数据；value inference 会修改所传合并池的标签列。

合并时 episode 元数据的文件索引按实际目标文件写入，包含分卷后的 chunk/file 编号；累计池可作为下一轮合并输入。已有训练池的索引修复与验证记录见[测试进展](../测试进展.md#2026-11-13)。

value 默认骨干为 `google/siglip-so400m-patch14-384` 与 `google/gemma-3-270m`，首次运行可能下载；Gemma 与 PaliGemma 访问权限分别确认。必须有明确成功/失败标签，不能把缺失标注静默当作正常失败样本。

## 独立 UR 评估的加载与检查

UR 入口加载 checkpoint 的 `config.json`、`model.safetensors`、`policy_preprocessor.json`、`policy_postprocessor.json` 和 processor state；state/action 的 QUANTILES 归一化与反归一化直接使用其中的 `q01/q99`，不使用 OpenPI 的 `norm_stats.json`，不重新读取训练数据统计。

输入为 19 维状态（TCP pose、speed、force 各 6 维，加 1 维夹爪状态）和两路原始 RGB 图像，映射到 checkpoint 的 `observation.images.exterior_image` / `observation.images.wrist_image`。LeRobot 负责图像预处理、状态归一化、状态文本编码和 tokenization。每轮调用 `predict_action_chunk()` 生成完整 50 步，反归一化后执行前 10 步（20 Hz），不保留 `select_action()` 的剩余动作队列。

`--check-checkpoint` 只检查文件、特征维度和统计，不加载模型/tokenizer，不连接硬件。`--check-model` 使用真实权重和合成观测验证完整推理；附加 `--device cpu --no-compile --sample-steps 1` 可做 CPU 单步检查，只覆盖当前进程。部署默认仍为 10 步采样与 `max-autotune`。

当前环境使用 `opencv-python-headless`，运行命令通过 `--no-visualize` 关闭预览；使用带 GUI 的 OpenCV 且有显示服务时，可去掉此参数。退出流程沿用 VLA-Precision 的复位和保存视频提示。

## 两套 SFT 评估入口

新入口复用旧入口的原生模型加载、预处理和反归一化；新入口在策略层截取前 10 步，旧入口在执行层截取前 10 步。完整预测均为 50 步；随机采样未固定噪声时，不保证两次动作逐项相同。

旧入口没有后台持续力控，新入口默认开启，可在 YAML 中关闭。旧旋转增益 2000/400 在公式中除以 rtde_freq=100，等效于新入口的 20/4，不能只按参数字面值比较。输出路径、记录选项分别保留，不影响共享模型配置。

图像浮点 padding=-1 后再执行 2*x-1 导致边缘=-3，是本仓库现有 PI05 路径的行为；训练与两套部署保持一致，此次未修复。是否影响真机效果需要单独对照，不能据此解释两入口之间的差异。

## 配置与数据约定更新规则

- 仅维护当前有效的数据 schema、模型输入输出、训练默认值及跨阶段约束；变化历史归入测试进展。
- 解释例外时给出对应代码、参数及适用范围，区分框架默认与本地实验适配。
- 不重复完整启动命令或实验结果；分别链接训练命令与结果摘要。
- 发现旧约定失效时替换正文，必要时在测试进展保留历史；规则置于文末。
