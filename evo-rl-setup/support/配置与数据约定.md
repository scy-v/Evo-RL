# 配置与数据约定

## SFT 设置

核对基准是仓库 `docs/source/pi05.mdx` 的 SFT 示例；主 README 第 6 步是后续 ACP，不是初始普通 SFT。

核心设置与 SFT 示例及默认值一致：bfloat16、全参、编译开启、梯度检查点开启、冻结视觉关闭、仅训练 expert 关闭、PEFT 关闭、ACP/RA-BC/RTC 关闭；默认图像处理、tokenizer、QUANTILES 归一化、chunk=50、内部 state/action 上限 32、token 长度 200 均未改动。
优化器沿用默认 AdamW：lr=2.5e-5、betas=(0.9,0.95)、eps=1e-8、weight_decay=0.01、梯度裁剪=1.0；默认 warmup=1000、decay=30000、末端 lr=2.5e-6。总步数小于 30000 时仓库会自动缩放调度。

用户指定的适配：4 卡、每卡 batch 16（全局 64）、30000 步、每 5000 步保存、本机数据与输出地址。W&B 只上传日志：enable=true、disable_artifact=true；HF 模型上传关闭，模型仅在本地保存。

## 离线选维度

训练数据适配位于 DatasetConfig、datasets/factory.py、datasets/state_selection.py；PI05 模型、处理器、训练循环保持基线实现。

`OBS_INDICES` 为从 1 开始的索引，按参数顺序选列，支持重排；也可用零基 `dataset.state_indices`，显式配置优先。数据加载完成后通过一次 HF map 得到整张新表，替换训练使用的表；取样和采 batch 时不再筛选。状态名称、维度和对应统计同步选择，count、动作、图像和原始数据文件不改。该功能要求 streaming=false。

原始数据有 48 维 state，当前 PI05 使用第 1–19 维；200 个 episode、67740 帧、15 Hz、两路图像、7 维动作。原有末端增量动作语义不变，未增加额外 delta transform。
推理与在线调用由调用方提供已准备好的 19 维输入，不通过 OBS_INDICES 筛选。

## 后续循环模板

训练命令第 5 步起尚未进行机器人或 GPU 实测。当前仓库提供独立的 VLA-Precision UR5e 推理入口（见[训练命令](../训练命令.md)第 4 节），但其日志不是 LeRobot 训练数据集；人工纠正采集仍需独立适配。ROLLOUT_CONFIG 不是已存在的配置文件，需要接入真实硬件、相机与遥操作。采集文件应和示范数据 schema 一致，且必须正确标记 episode_success；推理输入仍需由采集适配代码准备。

合并数据保留原始 schema，不落盘选维。value 命令按作者默认读取原始 state，训练和推理保持一致；只在 PI05 SFT/ACP 命令前内联 OBS_INDICES，不要全局 export 给 value 阶段。若后续也要求 value 只用选定维度，必须先同时适配其训练与推理入口，不能仅在训练时筛选。

value 默认使用 google/siglip-so400m-patch14-384 和 google/gemma-3-270m，首次运行会下载；Gemma 的访问权限与 PaliGemma 需要分别确认。value/ACP 需要带成功和失败标注的有效数据，未标注不能直接作为正常失败数据继续训练。

value inference 会把 value/advantage/indicator 写回本轮合并数据集。每轮名称、字段 tag 和输出目录独立；下轮合并上一轮累积数据与新 rollout，不能只用原示范和最新一轮而漏掉历史数据。

POLICY_CKPT 是 rollout 使用的当前策略；ACP_INIT_CKPT 是训练初始化来源，二者独立。模板初始设为 SFT checkpoint，之后默认保持该初始化；如需采用其他研究协议应显式调整。原 π*0.6/RECAP 的每轮预训练初始化规则不等于自动继承当前 rollout 策略；代码不会自动完成任何阶段切换。

## UR 推理加载与检查

UR 入口加载 checkpoint 的 `config.json`、`model.safetensors`、`policy_preprocessor.json`、`policy_postprocessor.json` 和 processor state；state/action 的 QUANTILES 归一化与反归一化直接使用其中的 `q01/q99`，不使用 OpenPI 的 `norm_stats.json`，不重新读取训练数据统计。

输入为 19 维状态（TCP pose、speed、force 各 6 维，加 1 维夹爪状态）和两路原始 RGB 图像，映射到 checkpoint 的 `observation.images.exterior_image` / `observation.images.wrist_image`。LeRobot 负责图像预处理、状态归一化、状态文本编码和 tokenization。每轮调用 `predict_action_chunk()` 生成完整 50 步，反归一化后执行前 10 步（20 Hz），不保留 `select_action()` 的剩余动作队列。

`--check-checkpoint` 只检查文件、特征维度和统计，不加载模型/tokenizer，不连接硬件。`--check-model` 使用真实权重和合成观测验证完整推理；附加 `--device cpu --no-compile --sample-steps 1` 可做 CPU 单步检查，只覆盖当前进程。部署默认仍为 10 步采样与 `max-autotune`。

当前环境使用 `opencv-python-headless`，运行命令通过 `--no-visualize` 关闭预览；使用带 GUI 的 OpenCV 且有显示服务时，可去掉此参数。退出流程沿用 VLA-Precision 的复位和保存视频提示。

## 两套 SFT 评估入口

新入口复用旧入口的原生模型加载、预处理和反归一化；新入口在策略层截取前 10 步，旧入口在执行层截取前 10 步。完整预测均为 50 步；随机采样未固定噪声时，不保证两次动作逐项相同。

旧入口没有后台持续力控，新入口默认开启，可在 YAML 中关闭。旧旋转增益 2000/400 在公式中除以 rtde_freq=100，等效于新入口的 20/4，不能只按参数字面值比较。输出路径、记录选项分别保留，不影响共享模型配置。

图像浮点 padding=-1 后再执行 2*x-1 导致边缘=-3，是本仓库现有 PI05 路径的行为；训练与两套部署保持一致，此次未修复。是否影响真机效果需要单独对照，不能据此解释两入口之间的差异。

## 配置与数据约定更新规则

- 仅维护当前有效的数据 schema、模型输入输出、训练默认值及跨阶段约束；变化历史归入测试进展。
- 解释例外时给出对应代码、参数及适用范围，区分框架默认与本地实验适配。
- 不重复完整启动命令或实验结果；分别链接训练命令与结果摘要。
- 发现旧约定失效时替换正文，必要时在测试进展保留历史；规则置于文末。
