# 1. PI05 全参 SFT 耗时对照

## 测试条件

- **配置与口径**：历史记录为 4 张 A800、每卡 batch 16（全局 64）、动作长度 50；Evo-RL 使用 LeRobot PyTorch PI05 并开启 `torch.compile(max-autotune)`，OpenPI 使用 `jax.jit`。Evo-RL 后续已核对 `run_01` 原始日志；OpenPI 沿用历史记录，本次未重新测量。

- **数据来源**：Evo-RL `run_01` 从 2026-10-20 19:06:35 至 10-21 09:08:10，稳定段排除前 1000 步，见[日志对照汇总](../outputs/acp_benchmark/sft_comparison.json)；OpenPI 数据来自本文件历史记录，未补齐原始日志。

# 2. Round 001：value 与 ACP 正式训练

## 测试条件

- **配置与口径**：4×A800 80GB、BF16、每卡 batch 16（全局 64），训练池 300 条/105610 帧。value 训练 10000 步、每 2500 步保存；ACP 从 PI05 基座全参训练 30000 步、每 5000 步保存，开启梯度检查点和编译。两者均为新运行，未 resume，路径为 `checkpoints/{value,acp}/round_001`。
- **统计口径**：value 每 2000 步、ACP 每 5000 步列一个节点；耗时为日志时间戳之差，首段从该阶段首条 INFO 起算，包含初始化/编译，后续区间包含期间发生的保存等待，但不含节点之后的保存。loss 为节点处最近 200 步的训练日志均值，不是整个 2000/5000 步区间均值，也不是验证 loss。

## 结论与采用方案

- **训练结果**：value 已完成，10000 步权重已用于全量覆盖标签；ACP 已完成 30000 步并保存，末个 200 步窗口 loss 为 0.044，最终权重的真机效果尚待验证。当前无独立验证集，训练 loss 下降不能证明未过拟合。
- **部署反馈**：用户测试 ACP 5000、20000 步权重后认为至少与 SFT 相当、轨迹更平滑，属于初步定性结果；分组成功率和最优 checkpoint 尚未确定，见[实验总结](实验总结.md)。

# 3. Summary 更新规则

## 通用要求

- 仅在用户明确要求写入或更新 summary 时修改正文；日常核查、讨论和代码变更不自动新增摘要主题。

- 按主题使用连续编号标题（1、2、3……），每个主题固定采用下列三个小标题；规则置于文末，新增主题时顺延编号。
